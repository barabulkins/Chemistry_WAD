## 1. Запуск и сборка проекта

### Требования
- Node.js версии 20+ (протестировано на Node.js v24)
- npm версии 10+

### Установка зависимостей
```bash
npm install
```

### Запуск сервера разработки (с поддержкой mock API)
```bash
npm run dev
```
Приложение откроется по адресу `http://localhost:5173`.  
Все запросы к `/api/samples` обрабатываются встроенным middleware Vite и отображаются во вкладке **Network (Сеть)** инструментов разработчика браузера (код ответа `200 OK`).

### Сборка для публикации (Production Build)
```bash
npm run build
```
Статические файлы будут сгенерированы в папку `dist/`.

## 2. Архитектура приложения и ограничения
- **Никакого Redux и Context API:** В соответствии с требованиями лабораторной работы управление состоянием реализовано исключительно на стандартных React-хуках (`useState`, `useEffect`, `useCallback`, `useMemo`) с передачей данных вниз по дереву компонентов через `props`.
- **Mock-сервис:** Получение данных производится через клиентский сервис `sampleService.ts` с HTTP-запросами к `/api/samples`, что обеспечивает наглядность во вкладке **Network** инструментов разработчика без необходимости запуска внешнего бэкенда.
- **Медиаресурсы по умолчанию:** При отсутствии или ошибке загрузки фото/видео карточка использует локальные ассеты `default-image.svg` и `default-video.mp4`.

## 3. Описание страниц приложения, кнопок и полей ввода

В соответствии с техническим заданием лабораторной работы и архитектурой системы, веб-приложение включает в себя **все 4 ключевые страницы** (представленные в нижней навигационной панели `BottomNav`), а также страницу детального паспорта химического образца (`SampleDetailView`).

### 3.1. Страница «Плитка» (`TileView`) — Каталог химических образцов
Основная витрина приложения, предназначенная для гостевого просмотра каталога химических образцов с возможностью фильтрации, сортировки и перехода к подробной информации.

- **Верхняя панель (`TopHeader`):**
  - Логотип и заголовок предметной области: «🧪 Технические образцы».
  - Информационный бейдж текущей роли: «Гость» (`Badge bg="primary"`).
  - Кнопка «Паспорт» (`Button variant="outline-secondary" size="sm"`): быстрый переход к аналитическому паспорту выбранного образца (иконка `InfoCircle`). При активном паспорте автоматически трансформируется в кнопку «Назад».
- **Информационный бейдж:** «Показано: N» — динамический счетчик отображаемых карточек, удовлетворяющих заданным условиям фильтра.
- **Компонент фильтрации и поиска (`FilterBar`):**
  - **Поле ввода «Поиск по названию образца»** (`Form.Control type="text"`): текстовое поле живого поиска по наименованию минерала или ключевым словам в описании.
  - **Ползунок диапазона «Объем газа (мл из 1 кг)»** (`Form.Range`): числовой слайдер от 0 до 100 мл с динамическим индикатором текущего выбранного значения.
  - **Выпадающий список сортировки «Сортировать по»** (`Form.Select`): выбор порядка ранжирования образцов (По умолчанию, По названию А-Я, По объему газа, По доле примесей, По лайкам).
  - **Кнопка «Найти»** (`Button variant="primary"`): отправляет HTTP-запрос `GET /api/samples?gas_volume=X` к mock API, инициируя сетевой запрос в DevTools Network.
  - **Кнопка сброса «Сбросить»** (`Button variant="outline-secondary"`): сбрасывает все фильтры и сортировку к исходным значениям и перезагружает полный список образцов.
- **Сетка карточек образцов (`SampleCard`):**
  - **Превью изображения:** карточка образца в формате 16:9; при отсутствии или сбое загрузки автоматически подставляет `default-image.svg` с бейджем «Изображение по умолчанию». Обработчик `onError` гарантирует отказоустойчивость.
  - **Бейдж статуса «Черновик»** (`Badge bg="danger"`): отображается для неопубликованных записей лаборанта (`status === 'draft'`).
  - **Счетчик лайков** (`❤️ N`): показатель популярности образца.
  - **Наименование образца:** заголовок минерала / исследуемого химического соединения.
  - **Характеристики химической реакции:** объем выделившегося газа (мл из 1 кг) и процентная доля примесей (%).
  - **Интерактивность карточки:** клик по карточке сохраняет образец и открывает страницу «Паспорт образца».

### 3.2. Страница «Лента» (`FeedView`) — Вертикальный медиа-просмотр
Полноэкранный вертикальный интерфейс для последовательного циклического просмотра химических образцов и видеозаписей лабораторных реакций.

- **Полноэкранный видеоплеер (`<video>`):**
  - Воспроизводит видеозапись протекания химической реакции с кислотой;
  - Поддерживает параметры `autoPlay`, `loop`, `muted`, `playsInline` и постер;
  - Автоматический fallback: при отсутствии или некорректном URL подставляет локальное видео `default-video.mp4` и выводит бейдж «Использовано видео по умолчанию».
- **Информационный оверлей поверх видео:**
  - Крупный заголовок с наименованием исследуемого минерала;
  - Системный идентификатор (ID) и бейдж статуса публикации («Опубликован»);
  - Развернутое текстовое описание состава и характера химической реакции.
- **Индикаторы параметров реакции (информационные плашки):**
  - **Капля (`Droplet`):** массовая доля примесей (%);
  - **Облако (`Cloud`):** объем выделившегося углекислого газа / водорода (мл);
  - **Сердечко (`Heart`):** количество отметок «Нравится».
- **Кнопка «Следующий образец»** (плавающая круглая кнопка с иконкой `ChevronDown`): отправляет сетевой запрос `GET /api/samples/feed?id=X&next=true` к mock API и циклически переключает ленту на следующий образец в коллекции.

### 3.3. Страница «Добавление» (`AddSampleView`) — Форма добавления нового химического образца
Интерфейс для добавления новых химических образцов, прикрепления медиаматериалов и публикации результатов анализов (пункт навигации «Добавление» в `BottomNav`).

- **Разграничение доступа (Role Guard):**
  - **Для роли «Гость»:** страница защищена ограничением доступа. Отображается информационный экран «Доступ ограничен: создание новых лабораторных образцов доступно только авторизованному лаборанту / создателю» с кнопкой перехода к авторизации.
  - **Для роли «Создатель»:** предоставляется полнофункциональная форма ввода данных.
- **Секция «Медиаресурсы образца»:**
  - **Поле выбора файла «Изображение (файл)»** (`Form.Control type="file" accept="image/*"`): выбор графического файла образца для загрузки в S3-хранилище (MinIO). При отсутствии файла подставляется изображение по умолчанию `default-image.svg`.
  - **Поле выбора файла «Видео реакции (файл)»** (`Form.Control type="file" accept="video/*"`): выбор видеофайла (mp4/webm) для воспроизведения в видеоленте. При отсутствии подставляется видео по умолчанию `default-video.mp4`.
- **Секция «Описание и параметры реакции»:**
  - **Текстовое поле «Название образца»** (`Form.Control type="text"`, обязательное): наименование исследуемого минерала (например, «Пирит гидротермальный»).
  - **Многострочное поле «Описание»** (`Form.Control as="textarea" rows={3}`): детальное описание кристаллической структуры, условий пробоподготовки и характера взаимодействия с реактивами.
  - **Числовое поле «Массовая доля примесей (%, в 1 кг)»** (`Form.Control type="number" step="0.1" min="0" max="100"`): расчетное содержание примесей в процентах.
  - **Числовое поле «Выделившийся газ (мл из 1 кг)»** (`Form.Control type="number" step="1" min="0"`): объем выделившегося газа при нормальных условиях.
- **Кнопки управления формы:**
  - **Кнопка «Создать черновик»** (`Button variant="outline-primary"`): сохраняет объект в коллекцию со статусом `draft` без публикации в гостевом каталоге.
  - **Кнопка «Создать и опубликовать»** (`Button variant="primary"`): валидирует форму, сохраняет образец и присваивает статус `published`, делая его доступным в «Плитке» и «Ленте».
  - **Кнопка «Очистить форму»** (`Button variant="secondary"`): сброс введенных значений полей и файлов.
  - **Индикаторы процесса:** анимация спиннера/лоадера на время отправки запроса и плашки уведомления об успешном создании или валидационной ошибке.

### 3.4. Страница «Вход» / «Авторизация» (`AuthView` / `LoginView`) — Форма входа в систему
Интерфейс для аутентификации пользователей и переключения между ролями «Гость» и «Создатель» (пункт навигации «Вход» в `BottomNav`).

- **Переключатель режимов (Табы):**
  - Вкладка «Вход» (авторизация существующего пользователя);
  - Вкладка «Регистрация» (создание нового профиля лаборанта).
- **Поля ввода формы входа («Вход»):**
  - **Поле «Электронная почта / Логин»** (`Form.Control type="email"`, placeholder `chemist@lab.ru`): ввод учетной записи с валидацией формата email.
  - **Поле «Пароль»** (`Form.Control type="password"`): защищенный ввод пароля с маскированием символов и кнопкой скрытия/показа пароля.
  - **Чекбокс «Запомнить меня»** (`Form.Check`): сохранение сессионного токена в `localStorage`/`cookie` для долговременной авторизации.
- **Поля ввода формы регистрации («Регистрация»):**
  - **Поле «Имя пользователя (ФИО лаборанта)»** (`Form.Control type="text"`): отображаемое имя автора услуг.
  - **Поле «Рабочий Email»** (`Form.Control type="email"`): корпоративная почта.
  - **Поля «Пароль» и «Подтверждение пароля»** (`Form.Control type="password"`): ввод и проверка пароля с валидацией минимальной длины.
- **Кнопки управления формы:**
  - **Кнопка «Войти»** (`Button variant="primary"`): отправка учетных данных на эндпоинт аутентификации, сохранение сессии и перевод интерфейса в режим создателя.
  - **Кнопка «Зарегистрироваться»** (`Button variant="success"`): регистрация нового пользователя и автоматический вход.
  - **Кнопка «Выйти из системы»** (`Button variant="danger"`): доступна авторизованному пользователю в профиле; завершает сессию, сбрасывает состояние в «Гость», очищает фильтры поиска и возвращает в гостевой каталог.

### 3.6. Нижняя навигационная панель (`BottomNav`)
Фиксированный `navbar` внизу экрана для быстрой мобильной и десктопной навигации, объединяющий все 4 страницы системы:
1. **«Лента» (`feed`)** — **доступна гостю**: активный пункт, мгновенно переключает экран на `FeedView`.
2. **«Добавление» (`add`)** — **недоступна для роли «Гость»**: стиль `disabled`, полупрозрачность (`opacity: 0.5`), курсор `not-allowed`, подсказка Tooltip о необходимости роли «Создатель».
3. **«Плитка» (`tile`)** — **доступна гостю**: активный пункт, переключает экран на каталог `TileView`.
4. **«Вход» (`auth`)** — **недоступна для роли «Гость»**: стиль `disabled`, полупрозрачность (`opacity: 0.5`), курсор `not-allowed`, подсказка Tooltip о входе лаборанта.

*В соответствии с заданием лабораторной работы, из 4 пунктов панели ровно 2 пункта («Лента» и «Плитка») являются активными и доступными для гостевого режима.*

## 4. Реализация компонентов, передаваемые Props и медиа по умолчанию

### 4.1. Реализация изображения и видео по умолчанию
В проекте предусмотрены файлы:
- `public/media/default-image.svg`
- `public/media/default-video.mp4`

В коде компонента `SampleCard.tsx`:
```tsx
const imageSrc = sample.image_url && sample.image_url.trim() !== ''
  ? sample.image_url
  : DEFAULT_IMAGE;

<Card.Img
  src={imageSrc}
  onError={(e) => { e.currentTarget.src = DEFAULT_IMAGE; }}
/>
```
Если поле `image_url` пустое (как у образцов «Доломит» и «Новый образец»), мгновенно применяется `DEFAULT_IMAGE`. Также обработчик `onError` страхует от битых внешних ссылок.
Аналогично в `FeedView.tsx` для видеопотока:
```tsx
const videoSrc = sample.video_url && sample.video_url.trim() !== ''
  ? sample.video_url
  : DEFAULT_VIDEO;
```

### 4.2. Передаваемые Props между компонентами
1. **`BottomNavProps`:**
   - `activeTab: 'feed' | 'tile'` — текущая активная вкладка;
   - `onSelectTab: (tab: 'feed' | 'tile') => void` — колбэк переключения экрана.
2. **`FilterBarProps`:**
   - `filters: SampleFilterOptions` — объект текущих критериев фильтрации;
   - `onChangeFilter: <K>(key: K, value: ...)` — функция обновления конкретного поля фильтра;
   - `onReset: () => void` — сброс фильтров;
   - `onApplyServerFilter: () => void` — запуск сетевого запроса к mock API;
   - `isLoading: boolean` — флаг сетевой активности.
3. **`SampleCardProps`:**
   - `sample: Sample` — объект образца (id, title, gas_volume, impurities_percent, likes, image_url...);
   - `onSelectSample: (sample: Sample) => void` — колбэк клика по карточке.
4. **`FeedViewProps`:**
   - `sample: Sample | null` — текущий образец для показа;
   - `onNextSample: () => void` — переход к следующему образцу (закольцованная лента);
   - `isLoading: boolean` — индикатор загрузки.
5. **`SampleDetailViewProps`:**
   - `sample: Sample` — объект образца для отображения в паспорте;
   - `onWatchInFeed: (sampleId: number) => void` — колбэк перехода к видеозаписи реакции в ленте.
6. **`TopHeaderProps`:**
   - `currentView: 'feed' | 'tile' | 'details'` — текущее активное представление;
   - `onOpenAbout: () => void` — колбэк открытия паспорта образца;
   - `onBackToGrid: () => void` — колбэк возврата к каталогу плитки.

## 5. Все используемые React-хуки

В проекте используются исключительно стандартные хуки React:
1. **`useState`:**
   - `currentView`: переключение между страницами `'tile'`, `'feed'` и `'details'`;
   - `samples`: массив загруженных образцов;
   - `feedSample`: активный образец для ленты;
   - `selectedSample`: образец для страницы детального паспорта;
   - `filters`: состояние формы фильтрации;
   - `isLoading`: индикатор ожидания сетевого ответа.
2. **`useEffect`:**
   - **Эффект 1 (первичная загрузка каталога):** срабатывает один раз при монтировании компонента `App` (`[]`) и запрашивает коллекцию карточек с `/api/samples`.
   - **Эффект 2 (первичная загрузка ленты):** срабатывает при монтировании и запрашивает первый образец для экрана ленты с `/api/samples/feed`.
3. **`useCallback`:**
   - Мемоизирует функции `loadCatalog`, `loadFeed`, `handleApplyServerFilter`, `handleResetFilter`, предотвращая лишние ререндеры дочерних компонентов при изменении других состояний.
4. **`useMemo`:**
   - Мемоизирует вычисление отфильтрованного и отсортированного списка `processedSamples`. Пересчитывается только при изменении `samples`, `searchQuery` или `sortBy`.

## 7. Ответы на контрольные вопросы

### 1. Что такое React?
**React** — это декларативная JavaScript/TypeScript-библиотека с открытым исходным кодом для создания пользовательских интерфейсов (SPA). React основан на компонентном подходе, при котором UI разбивается на изолированные переиспользуемые блоки (компоненты). React использует Virtual DOM (виртуальное дерево объектов) для оптимизации обновлений реального DOM браузера посредством алгоритма согласования (reconciliation / React Fiber).

### 2. Props и состояние (State) — отличия
- **`props` (свойства)** — неизменяемые (read-only) входные параметры, передаваемые от родительского компонента дочернему сверху вниз (однонаправленный поток данных). Дочерний компонент не имеет права мутировать свои props.
- **`state` (состояние)** — внутреннее изменяемое хранилище данных компонента, определяющее его текущий вид и поведение. При изменении состояния через специальную функцию (`setSomething`) React инициирует повторный рендеринг компонента и его дочерних элементов.

### 3. Компонент и элемент — в чем разница?
- **Элемент React (React Element)** — легковесный, неизменяемый объект JavaScript, описывающий, что именно должно появиться на экране (виртуальный узел DOM: `{ type: 'div', props: { children: 'Hello' } }`). Создается вызовом `React.createElement` или синтаксисом JSX.
- **Компонент React (React Component)** — функция (или класс), которая принимает `props` на вход и возвращает React-элемент или их дерево. Компонент инкапсулирует логику, состояние и жизненный цикл.

### 4. Хуки useState и useEffect
- **`useState`** — хук для объявления переменной состояния в функциональном компоненте. Возвращает кортеж из двух значений: текущее состояние и функцию для его обновления: `const [state, setState] = useState(initialValue);`.
- **`useEffect`** — хук для выполнения побочных эффектов (Side Effects): сетевых запросов, подписок на события, манипуляций с таймерами. Принимает функцию эффекта и массив зависимостей `[deps]`. При пустом массиве `[]` эффект запускается один раз при монтировании (аналог `componentDidMount`).

### 5. Жизненный цикл компонента
Жизненный цикл функционального компонента охватывает три основные фазы:
1. **Монтирование (Mounting):** инициализация `useState`, первый рендер и выполнение `useEffect` с пустым массивом зависимостей `[]`.
2. **Обновление (Updating):** изменение `props` или `state`, повторный вызов функции компонента (re-render) и срабатывание `useEffect` с указанными зависимостями `[a, b]`.
3. **Размонтирование (Unmounting):** удаление компонента из DOM, выполнение функции очистки (cleanup function), возвращаемой из `useEffect`.

### 6. Сравнение Vite и Babel
- **Babel** — классический транспайлер JavaScript. Преобразует современный синтаксис ECMAScript (ES6+) и JSX в обратно совместимый JavaScript (ES5) для старых браузеров. Работает на уровне синтаксического AST-дерева файлов.
- **Vite** — современный инструмент сборки нового поколения. В режиме разработки (Dev) Vite использует нативные ES-модули браузера (No-bundle Dev Server) и сверхбыстрый препроцессор `esbuild` (написанный на Go), что дает мгновенный старт сервера и Hot Module Replacement (HMR). Для production-сборки Vite использует оптимизированный бандлер Rollup.
